# Политика безопасности

## Поддерживаемые версии

До первого публичного релиза исправления безопасности выпускаются только для
ветки `main`. После релиза поддерживается последняя минорная версия; статус
предыдущих версий будет указан здесь.

## Как сообщить об уязвимости

Не создавайте публичный issue и не включайте секреты или пользовательские данные
в общедоступные материалы.

Предпочтительный канал — **Report a vulnerability** на вкладке Security этого
репозитория. Он создаёт приватный GitHub Security Advisory. Если кнопка
недоступна, создайте issue только с просьбой предоставить приватный канал и без
технических деталей уязвимости.

В отчёте полезно указать:

- затронутую версию или commit;
- воспроизводимый сценарий и ожидаемое влияние;
- минимальный proof of concept без реальных credentials и персональных данных;
- известные способы смягчения риска.

Мы стремимся подтвердить получение в течение трёх рабочих дней, предоставить
первичную оценку в течение семи рабочих дней и согласовать раскрытие после
доступности исправления. Срок может измениться в зависимости от сложности и
координации с внешними поставщиками.

## Область ответственности

В область проекта входят исходный код, официальные release artifacts и
конфигурация CI этого репозитория. Уязвимости Yandex Cloud, GitHub и сторонних
пакетов следует также сообщать соответствующему поставщику; мы поможем оценить,
затрагивает ли проблема этот проект.
