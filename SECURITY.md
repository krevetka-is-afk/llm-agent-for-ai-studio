# Безопасность

## Поддерживаемые версии

До релиза исправления безопасности выпускаются для `main`. После релиза
поддерживается последняя минорная версия.

## Как сообщить об уязвимости

Используйте **Report a vulnerability** на вкладке Security. Если кнопка
недоступна, создайте issue с просьбой открыть приватный канал, но не публикуйте
технические детали.

В отчёте укажите:

- версию или commit;
- способ воспроизведения;
- возможное влияние;
- безопасный proof of concept без credentials и персональных данных;
- известный workaround, если он есть.

Не прикладывайте реальные API-ключи, пользовательские файлы и неочищенные логи.

## Область проекта

Мы принимаем отчёты об исходном коде, release artifacts и CI этого
репозитория. Проблемы Yandex Cloud, GitHub и сторонних пакетов также следует
сообщать их разработчикам.

## Защита модельного контура

Builder и тестовый запуск агентов используют входной фильтр, приоритетную
системную политику и проверку результата перед показом. Данные пользователя,
загруженные документы, результаты поиска и tool output не считаются
доверенными инструкциями. Заблокированный контент не коммитит состояние
диалога; связанные remote outputs не выдаются пользователю и удаляются. При
ранней блокировке они удаляются без скачивания.

Prompt injection нельзя считать полностью решённой одной эвристикой или
system prompt. Сообщайте о воспроизводимых обходах приватно: безопасный пример
будет добавлен в регрессионный набор без публикации чувствительного контента.
